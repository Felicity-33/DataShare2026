# 链承共予 · DataShare —— 个人数据授权与托管结算 DApp

> 区块链大赛参赛项目 · 让数据成为资产，每一次授权都有迹可循
>
> 合约版本 **v4.4** · 前端/文档版本 **v4.5** · 更新日期 2026-09-27

## 一、项目简介

**链承共予 · DataShare** 是一个基于区块链的个人数据授权与托管结算 DApp，面向个人数据"确权难、授权不透明、收益无保障"的现实痛点，构建"注册确权 → 授权 → 充值押金 → 托管调用 → 交付凭证 → 结算 / 争议 → 提现 → 审计"的完整业务闭环。系统运行于本地 Ganache 测试链（ChainID 1337），用户、企业、监管三角角色由智能合约的 `AccessControl` 权限体系统一管理。

资金与数据两条主线均由合约强制执行：企业调用数据的费用**先进合约托管**，挑战期满或企业提前结算后才解锁给数据所有者，期间企业可申诉、监管可裁决；原始个人数据**始终不上链**，链上只保存三项极小凭证 —— 链下索引 `dataRef`（数据在哪）、内容摘要 `deliveryHash`（有没有被改）、权属承诺 `commitment`（数据归谁）。确权环节需提交一枚 Groth16 零知识权属证明，证明"掌握权属密钥"而不暴露密钥本身；任何人用同一份链下数据重算摘要，即可与链上凭证比对验证交付真实性。

六大机制构成核心创新：**托管式结算（资金有救济）**、**链上交付凭证（数据不出域）**、**合约自证审计（证据不可伪造）**、**链上标准价（杜绝乱定价）**、**链上信誉分**、**监管权力双向约束（可裁决不可动钱、可审计不可窥探）**。另实装 AI 辅助能力（自然语言需求解析 / 匹配理由 / 合规提示），AI 只做辅助解读、不参与链上决策。

## 二、核心功能

系统围绕三角角色交付三端工作台，各功能模块"做了什么、解决了什么"如下表：

| 功能模块 | 具体实现 | 解决的问题 |
| --- | --- | --- |
| 字段级确权与授权（用户端） | 数据字段逐条上链确权（含 ZK 权属证明），按字段、按企业授权 / 撤销，撤权即时生效 | 数据主权旁落、"一揽子授权"用户不知情 |
| 押金制托管调用（企业端） | 企业充值押金后调用数据，金额由合约按链上标准价计算，费用进入合约托管并生成交付凭证哈希 | 先付款后交付、劣质交付无救济 |
| 提前结算与申诉 | 企业可在挑战期内（演示值 600 秒）提前结算立即解锁，或发起争议锁定资金待裁决 | 一次性转账缺乏售后通道 |
| 争议裁决与信誉分（监管端） | 监管可裁决资金归属（退款企业 / 放款用户）、标记失信；企业信誉分低于阈值自动暂停调用权限 | 争议无出口、劣质企业无惩戒 |
| 合约自证审计 | 未授权、余额不足等拦截留痕由合约在业务校验中自动写入、原因由合约判定，企业无法伪造或选择性上报 | 审计数据由被监管方自行上报、可被操纵 |
| 链上标准价 | 单价为合约公开常量（按次 0.05 / 按天 0.5），业务函数不接收传入价格，金额一律由合约计算 | 乱定价、哄抬与价格欺诈 |
| AI 辅助匹配 | 自然语言需求解析为结构化条件，基于链下数据集真实属性给出推荐字段与逐条匹配理由；本地规则引擎实现，结果可复现 | 数据供需匹配依赖人工筛选 |

用户端另提供「企业取用凭证」列表：谁在何时取走了哪条字段、凭证哈希与结算状态全程可查，落实《个人信息保护法》"告知—同意"与知情权。

## 三、技术架构

系统采用"链下存数据、链上存索引与承诺"的分层架构：链上承载不可篡改的关键摘要，链下承载业务数据本体，二者通过哈希相互印证。主要技术选型如下：

| 层次 | 选型 | 用途说明 |
| --- | --- | --- |
| 智能合约 | Solidity 0.8.24 + OpenZeppelin（AccessControl / ReentrancyGuard） | DataShare 主合约（角色、确权、授权、托管、争议、信誉分）与 Groth16 验证器（接口外部调用） |
| 零知识证明 | circom 电路 + Groth16 + snarkjs | 权属承诺 `commitment = Poseidon(secret, owner)`，证明在浏览器本地生成、密钥不出本机 |
| 开发框架 | Hardhat 2.x | 编译、测试、部署；前端 ABI 由编译产物自动生成，杜绝手写 ABI 与链上不一致 |
| 测试网络 | Ganache（RPC 127.0.0.1:7545，ChainID 1337） | 本地模拟链，不接入真实公链 |
| 链交互 | Ethers.js v6（BrowserProvider） | 连接 MetaMask 与合约交互 |
| 前端 | React 18 + Vite + TailwindCSS + Recharts | 三端工作台（15 个组件）；贯穿实时区块高度、每笔操作"已上链确认条"、合约版本校验等区块链特性 |
| 链下数据 | 17 个分类 JSON 数据文件（`frontend/public/data/`） | 数据本体不上链、不参与前端打包；`dataRef` 与存储实现解耦，可平滑迁移至数据库、对象存储或联盟链环境 |

## 四、应用价值

本项目面向数据要素市场化中"个人数据确权、授权与收益分配"这一薄弱环节，用区块链提供低成本信任基础设施，方案对齐"数据二十条"关于数据产权、流通交易与收益分配的制度设计。

- **对用户**：数据主权回归个人 —— 字段级确权、可随时撤回的授权、托管分账让"数据被使用即有收益"，取用凭证全程可查，落实"告知—同意"与最小必要原则；
- **对企业**：获得可验证的授权链条与数据交付凭证，链上标准价提供统一价格基准，信誉分提供可信度参考，降低合规与信任成本；
- **对监管**：全链路链上留痕与合约自证审计显著降低取证与追责成本；监管权限被合约约束为"可裁决、不可动钱"，从机制上杜绝权力滥用。

## 五、测试与质量

合约测试共 **56 个用例**，覆盖角色控制、ZK 确权、链上标准价、授权管理、托管结算、争议与监管裁决、信誉分、平台分账与订单状态，全部通过。另有 ZK 链路自检，自动完成"生成证明 → 本地验证 → 确认篡改承诺必被拒绝"的反例校验。

前端建立四道自检防线（JSX 未定义标识符扫描、SSR 真渲染检查、Poseidon 前后端一致性校验、真实浏览器冒烟检查），用于拦截"构建通过但浏览器运行异常（如整页白屏）"一类只在真实浏览器中暴露的问题。

## 六、运行说明

项目运行依赖 Node.js v18+、本地 Ganache 测试链（RPC 127.0.0.1:7545，ChainID 1337）与 MetaMask 钱包。依赖安装、合约编译部署与日常启动均已脚本化：双击根目录 `start.bat`（或执行 `npm start`）即可自动完成本地链启动、合约版本校验与前端打开（`http://localhost:5174`）。现场演示步骤与话术详见 `docs/演示速查卡.md` 与 `docs/演示视频脚本.md`，开发期完整操作命令见 `docs/目录说明.md` 的「日常操作速查」。
